Give a language model the same math problem twice and it may take two different routes. Supervised fine-tuning (SFT) learns from worked examples. Reinforcement learning (RL) lets the model try its own answers and score them with a verifier or a reward model. A correct solution can earn credit even if nobody wrote out that particular route.

## Rewards, rollouts, and policies

### The basic setup

A policy $$\pi_\theta$$ samples an action $$a_t$$ in state $$s_t$$. The environment returns a reward $$r_t$$ and the next state. The objective is the expected discounted return over a trajectory $$\tau$$.

$$
G_t=\sum_{k=t}^{T}\gamma^{k-t}r_k,\qquad
J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[G_1].
$$

For a language model, the state is the prompt and the generated prefix, $$s_t=(x,y_{<t})$$, and the action is the next token $$y_t$$. A math verifier can give a single reward at the end. Human-feedback training can fill the same role with a learned reward $$R_\psi(x,y)$$.

$$
R(x,y)=\mathbf 1_{\{\operatorname{answer}(y)=y^\star(x)\}},\qquad
r_t=\mathbf 1_{\{t=T\}}R(x,y),\qquad \gamma=1.
$$

### On-policy, off-policy, online, and offline

| Question | Two answers |
|---|---|
| Who generated the data? | **On-policy** uses the same policy for sampling and learning. **Off-policy** learns about a target policy from data generated by a different behavior policy. |
| When is data collected? | **Online** training can collect fresh experience as it learns. **Offline** training starts with a fixed dataset. |

Q-learning can collect experience online and still be off-policy. PPO collects fresh rollouts from a snapshot of the policy. That snapshot becomes stale as we take more updates on the same batch.

## Learning a policy

### Policy gradient and REINFORCE

A token sample and an exact-match checker are discrete. The trick is to differentiate the *probability* of the rollout and use the checker’s score as a weight.

$$
\begin{aligned}
p_\theta(\tau)&=p(s_1)\prod_{t=1}^{T}
       \pi_\theta(a_t\mid s_t)P(s_{t+1},r_t\mid s_t,a_t),\\
\nabla_\theta J
 &=\mathbb E_{\tau\sim\pi_\theta}[G_1\nabla_\theta\log p_\theta(\tau)]\\
 &=\mathbb E_{\tau\sim\pi_\theta}
 \left[\sum_{t=1}^{T}\gamma^{t-1}G_t\,\nabla_\theta\log\pi_\theta(a_t\mid s_t)\right].
\end{aligned}
$$

The environment factors are fixed with respect to $$\theta$$. The action score has conditional mean zero, so rewards earned before the action drop out. REINFORCE plugs in the observed $$G_t$$, which can vary widely between rollouts.

~~~python
class REINFORCE:
    def loss(self, logp, rewards, gamma=0.99):
        rewards = rewards.detach()
        returns = torch.zeros_like(rewards)
        future = rewards.new_zeros(())
        for t in range(len(rewards) - 1, -1, -1):
            future = rewards[t] + gamma * future
            returns[t] = future
        discount = gamma ** torch.arange(len(rewards), dtype=rewards.dtype, device=rewards.device)
        return -(logp * discount * returns).sum()
~~~

</details>

### Actor-critic

If a prompt is easy, even an ordinary response may score well. A critic estimates what the policy would normally earn in the state, giving the actor a more informative weight.

$$
\begin{aligned}
Q^\pi(s,a)&=\mathbb E_\pi[G_t\mid s_t=s,a_t=a],&
V^\pi(s)&=\mathbb E_\pi[G_t\mid s_t=s],\\
A^\pi(s,a)&=Q^\pi(s,a)-V^\pi(s),&
\mathbb E_{a\sim\pi_\theta}
 \big[b(s)\nabla_\theta\log\pi_\theta(a\mid s)\big]
 &=b(s)\nabla_\theta\sum_a\pi_\theta(a\mid s)=0.
\end{aligned}
$$

The last identity lets us subtract any action-independent baseline $$b(s)$$ without changing the expected gradient. With the exact critic, the conditional mean of the one-step TD error below is $$A^\pi(s_t,a_t)$$.

#### Generalized advantage estimation

GAE combines short-horizon TD errors with a decay controlled by $$\lambda$$. Let $$d_t=1$$ on a terminal transition.

$$
\begin{aligned}
\delta_t&=r_t+\gamma(1-d_t)V(s_{t+1})-V(s_t),\\
\hat A_t&=\delta_t+\gamma\lambda(1-d_t)\hat A_{t+1},\qquad
\hat A_{T+1}=0.
\end{aligned}
$$

At $$\lambda=0$$, the estimate is one TD error. At $$\lambda=1$$ over a complete episode, the value terms telescope to $$G_t-V(s_t)$$. The actor weights its score by a fixed $$\hat A_t$$, and the critic regresses on $$V(s_t)+\hat A_t$$ with that target held fixed.

~~~python
class ActorCritic:
    def advantage(self, reward, value, next_value, terminal, gamma=0.99, lam=0.95):
        bootstrap = next_value.detach().masked_fill(terminal, 0)
        delta = reward.detach() + gamma * bootstrap - value.detach()
        advantage = torch.zeros_like(delta)
        future = torch.zeros_like(delta[..., 0])
        for t in range(delta.shape[-1] - 1, -1, -1):
            future = delta[..., t] + gamma * lam * (~terminal[..., t]) * future
            advantage[..., t] = future
        return advantage

    def loss(self, logp, reward, value, next_value, terminal, gamma=0.99, lam=0.95):
        advantage = self.advantage(reward, value, next_value, terminal, gamma, lam)
        target = value.detach() + advantage
        time = torch.arange(logp.shape[-1], dtype=logp.dtype, device=logp.device)
        actor = -(gamma ** time * advantage * logp).sum(dim=-1).mean()
        critic = 0.5 * (value - target).square().mean()
        return actor + critic
~~~

</details>

## Learning values and planning

### Q-learning

A value-based agent can choose an action by ranking its estimates $$Q(s,a)$$. Q-learning backs up the best next action, even when the behavior policy is still exploring.

$$
\begin{aligned}
Q^*(s,a)&=\mathbb E[r+\gamma(1-d)\max_b Q^*(s',b)\mid s,a],\\
Q(s,a)&\leftarrow Q(s,a)
      +\alpha\big[r+\gamma(1-d)\max_b Q(s',b)-Q(s,a)\big].
\end{aligned}
$$

This is a model-free TD update from a real transition. The greedy target and an exploration policy can differ, so the update is off-policy.

~~~python
class QLearning:
    def __init__(self, states, actions, lr=0.1, gamma=0.99):
        self.q = torch.zeros(states, actions)
        self.lr, self.gamma = lr, gamma

    def act(self, state, epsilon=0.1):
        if torch.rand(()) < epsilon:
            return int(torch.randint(self.q.shape[1], ()))
        return int(self.q[state].argmax())

    def update(self, state, action, reward, next_state, terminal):
        target = reward
        if not terminal:
            target = reward + self.gamma * self.q[next_state].max()
        self.q[state, action] += self.lr * (target - self.q[state, action])
~~~

</details>

### Dyna-Q

Value-based describes how we choose actions. Model-based describes whether we use a model of transitions and rewards for planning. Dyna-Q does both. It uses the very same Q update on real transitions and on extra transitions generated by a learned model.

$$
\text{real }(s,a,r,s',d)
 \ \longrightarrow\ Q\text{ update},\quad \widehat M(s,a)\leftarrow(r,s',d).
$$

$$
(\tilde s,\tilde a)\ \text{sampled from visited pairs}
 \ \longrightarrow\ \widehat M(\tilde s,\tilde a)
 \ \longrightarrow\ Q\text{ update}.
$$

In a deterministic maze, a table with the last outcome for each pair is enough to simulate one step.

class DynaQ(QLearning):
    def __init__(self, states, actions, lr=0.1, gamma=0.99, planning_steps=5):
        super().__init__(states, actions, lr, gamma)
        self.model = {}
        self.planning_steps = planning_steps

    def update(self, state, action, reward, next_state, terminal):
        transition = (state, action, reward, next_state, terminal)
        super().update(*transition)
        self.model[state, action] = transition
        for simulated in random.choices(list(self.model.values()), k=self.planning_steps):
            super().update(*simulated)

## Keeping a policy update small

Write $$\mu$$ for the policy that actually sampled the batch. At a fixed state, the importance ratio changes the action distribution inside the expectation, assuming $$\mu$$ covers the actions used by $$\pi_\theta$$.

$$
w_t=\frac{\pi_\theta(a_t\mid s_t)}{\mu(a_t\mid s_t)},\qquad
\mathbb E_{a\sim\mu(\cdot\mid s)}[w_t f(s,a)]
=\mathbb E_{a\sim\pi_\theta(\cdot\mid s)}[f(s,a)].
$$

The local surrogate $$J_{\rm surr}=\mathbb E_\mu[w_t\hat A_t]$$ keeps the sampled states and their advantages fixed.

### Natural policy gradient

An ordinary step measures distance in parameter space. The natural policy gradient (NPG) uses the local KL curvature to measure how far the *policy* moves.

$$
\begin{aligned}
\bar D(\theta)&=\mathbb E_{s\sim\mu}D_{\rm KL}
 \big(\mu(\cdot\mid s)\,\|\,\pi_\theta(\cdot\mid s)\big),\\
\bar D(\theta_{\rm old}+\Delta)&\simeq \tfrac12\Delta^\top F\Delta,\qquad
g=\nabla J_{\rm surr}(\theta_{\rm old}),\qquad
\Delta_{\rm NPG}=\eta F^{-1}g .
\end{aligned}
$$

Here $$F=\nabla^2\bar D(\theta_{\rm old})$$. The example adds a small ridge to the linear solve.

class NaturalPolicyGradient:
    def direction(self, gradient, fisher, damping=1e-5):
        eye = torch.eye(gradient.numel(), dtype=gradient.dtype, device=gradient.device)
        return torch.linalg.solve(fisher + damping * eye, gradient)
~~~

</details>

### TRPO

Trust Region Policy Optimization (TRPO) gives the mean KL a budget. The basic update scales the natural-gradient direction to fit the local budget, then checks the actual KL and surrogate with a line search.

$$
\max_\theta J_{\rm surr}(\theta)\quad\text{subject to}\quad
\bar D(\theta)\le \delta,\qquad
\Delta_{\rm local}
 = \sqrt{\frac{2\delta}{d^\top Fd}}\,d,\quad d=F^{-1}g.
$$

</figure>

<details markdown="1">
<summary>Python</summary>

~~~python
class TRPO(NaturalPolicyGradient):
    def step(self, params, surrogate, mean_kl, limit=0.01, damping=1e-5):
        old = params.detach()
        gradient = torch.func.grad(surrogate)(old)
        fisher = torch.func.hessian(mean_kl)(old)
        direction = self.direction(gradient, fisher, damping)
        curvature = direction @ fisher @ direction
        if curvature <= 0:
            return old
        delta = direction * (2 * limit / curvature).sqrt()
        base = surrogate(old)
        for i in range(10):
            candidate = old + (0.5 ** i) * delta
            if mean_kl(candidate) <= limit and surrogate(candidate) > base:
                return candidate
        return old
~~~

</details>

### PPO

Proximal Policy Optimization (PPO) clips the gain from a move that already went far enough. For a good action, going from ratio $$1.2$$ to $$1.3$$ earns the same surrogate value when the upper threshold is $$1.2$$.

$$
\begin{aligned}
C_{\ell,u}(w,A)&=\min\big(wA,\operatorname{clip}(w,\ell,u)A\big)\\
 &=\begin{cases}
 A\min(w,u),&A>0,\\
 A\max(w,\ell),&A<0,\\
 0,&A=0,
 \end{cases}\\
J_{\rm PPO}&=\mathbb E_\mu\!\left[C_{1-\epsilon,\,1+\epsilon}(w_t,\hat A_t)\right].
\end{aligned}
$$

On the flat branch the sample contributes zero policy gradient. Other samples can still move that probability. In actor-critic PPO the critic supplies $$\hat A_t$$, often via GAE.

## Policy optimization for language models

### What a completion is worth

In preference-based PPO, one common way to preserve the starting model's behavior is to include a reference penalty in the rollout reward. The token log-ratios sum to the response log-ratio.

$$
r_t=\mathbf 1_{\{t=T\}}R(x,y)
 -\beta\log\frac{\mu(y_t\mid x,y_{<t})}{\pi_{\rm ref}(y_t\mid x,y_{<t})},
\qquad
\sum_t\log\frac{\mu(y_t\mid x,y_{<t})}{\pi_{\rm ref}(y_t\mid x,y_{<t})}
 =\log\frac{\mu(y\mid x)}{\pi_{\rm ref}(y\mid x)} .
$$

The rollout policy $$\mu$$ supplies the denominator of the update ratio. The fixed reference $$\pi_{\rm ref}$$ supplies the target of the KL penalty.

### GRPO

Group Relative Policy Optimization (GRPO) estimates the baseline by asking the model to answer the same prompt $$G$$ times. One reward gives every token in a response the same advantage, and the per-response average gives every response the same weight.

$$
\begin{aligned}
y_i&\sim\mu(\cdot\mid x),\quad R_i=R(x,y_i),\quad
A_i^0=R_i-\bar R,\quad A_i=\frac{A_i^0}{\sigma_R+\varepsilon},\\
s_{it}&=(x,y_{i,<t}),\qquad
w_{it}=\frac{\pi_\theta(y_{it}\mid s_{it})}{\mu(y_{it}\mid s_{it})},\\
J_{\rm GRPO}
 &=\mathbb E_\mu\!\left[\frac1G\sum_i\frac1{T_i}\sum_t
      \big(C_{1-\epsilon,\,1+\epsilon}(w_{it},A_i)-\beta k_{it}\big)\right].
\end{aligned}
$$

Here $$\bar R$$ and $$\sigma_R$$ are the within-prompt mean and standard deviation. The original method adds a separate reference penalty. At a fixed prefix, $$k_{it}$$ estimates the indicated KL under current-policy sampling. With old rollouts, the same expression is a sampled penalty.

$$
u_{it}=\log\frac{\pi_{\rm ref}(y_{it}\mid s_{it})}{\pi_\theta(y_{it}\mid s_{it})},
\qquad k_{it}=e^{u_{it}}-1-u_{it},
\qquad \mathbb E_{y_{it}\sim\pi_\theta}[k_{it}]
 =D_{\rm KL}(\pi_\theta\|\pi_{\rm ref}).
$$

~~~python
class GRPO:
    def advantage(self, rewards):
        rewards = rewards.detach()
        centered = rewards - rewards.mean(dim=-1, keepdim=True)
        return centered / (rewards.std(dim=-1, keepdim=True, correction=0) + 1e-6)

    def loss(self, logp, old_logp, rewards, mask, eps=0.2, ref_logp=None, beta=0.0):
        advantage = self.advantage(rewards).unsqueeze(-1)
        log_w = log_ratio(logp, old_logp, mask)
        objective = clipped_objective(log_w, advantage, 1 - eps, 1 + eps)
        if ref_logp is not None and beta:
            u = -(logp - ref_logp.detach()).masked_fill(~mask, 0)
            objective = objective - beta * (u.expm1() - u)
        return -masked_mean(objective, mask, dim=-1).mean()
~~~

</details>

The variants below share a familiar problem. A solution earns one reward, but the update is made of many token gradients. Which responses enter the batch, how we average their gradients, and how far we let an old rollout pull the current policy are three separate choices.

## What the GRPO variants change

### Reward and length weighting

#### Dr. GRPO

Take two correct solutions in a mixed group, one twice as long as the other. In GRPO each token of the shorter one gets twice the weight before clipping. The group standard deviation also rescales the update across prompts. Dr. GRPO removes both divisors and uses a fixed generation budget $$L$$ for scale.

$$
J_{\rm Dr.GRPO}=\mathbb E_\mu\!\left[
  \frac1{GL}\sum_{i,t} C_{1-\epsilon,\,1+\epsilon}(w_{it},A_i^0)
\right].
$$

~~~python
class DrGRPO:
    def loss(self, logp, old_logp, rewards, mask, budget, eps=0.2):
        centered = (rewards - rewards.mean(dim=-1, keepdim=True)).detach()
        log_w = log_ratio(logp, old_logp, mask)
        objective = clipped_objective(log_w, centered.unsqueeze(-1), 1 - eps, 1 + eps)
        return -objective.masked_fill(~mask, 0).sum(dim=-1).mean() / budget
~~~

</details>

#### DAPO

If every answer in a group gets the same binary reward, there is no relative signal to learn from. DAPO resamples until it has mixed groups, averages over all their response tokens, and raises the upper clip to give positive-advantage tokens more room to grow.

$$
\begin{aligned}
0&<\sum_i\mathbf1_{\{\operatorname{correct}(y_i)\}}<G, \qquad
\epsilon_{\rm high}>\epsilon_{\rm low},\\
J_{\rm DAPO}&=\mathbb E_{\rm kept}\!\left[
\frac{\sum_{i,t} C_{1-\epsilon_{\rm low},\,1+\epsilon_{\rm high}}(w_{it},A_i)}
     {\sum_i T_i}\right].
\end{aligned}
$$

A soft penalty reduces the reward as a response enters the last $$B$$ tokens before the cap $$L_{\max}$$. The group advantages use the shaped rewards.

$$
R_i^{\rm shaped}=R_i-
 \operatorname{clip}\!\left(\frac{T_i-(L_{\max}-B)}{B},\,0,\,1\right).
$$

~~~python
class DAPO(GRPO):
    def shaped_reward(self, reward, length, cap, buffer):
        return reward - ((length - (cap - buffer)) / buffer).clamp(0, 1)

    def loss(self, logp, old_logp, rewards, correct, mask, eps_low=0.20, eps_high=0.28):
        keep = correct.any(dim=-1) & ~correct.all(dim=-1)
        valid = mask & keep[:, None, None]
        advantage = self.advantage(rewards).unsqueeze(-1)
        log_w = log_ratio(logp, old_logp, valid)
        objective = clipped_objective(log_w, advantage, 1 - eps_low, 1 + eps_high)
        per_prompt = masked_mean(objective, valid, dim=(-2, -1))
        return -masked_mean(per_prompt, keep)
~~~

</details>

### Which ratios get clipped?

#### GSPO

GRPO can clip two tokens in the same answer differently, even though both inherit the same final score. Group Sequence Policy Optimization (GSPO) takes the geometric mean of the token ratios and clips once for the whole answer. This gives its tokens a common multiplier on the log-probability gradient.

$$
\begin{aligned}
s_i&=\exp\!\left(\frac1{T_i}\sum_t\log w_{it}\right)
 =\left(\frac{\pi_\theta(y_i\mid x)}{\mu(y_i\mid x)}\right)^{1/T_i},\\
J_{\rm GSPO}&=\mathbb E_\mu\!\left[
     \frac1G\sum_i C_{1-\epsilon,\,1+\epsilon}(s_i,A_i)\right],\\
\nabla_\theta s_i&=\frac{s_i}{T_i}\sum_t\nabla_\theta\log\pi_\theta(y_{it}\mid s_{it}).
\end{aligned}
$$

The length root tempers the scale of the ratio. A clipped response loses its entire contribution from this term.

class GSPO(GRPO):
    def loss(self, logp, old_logp, rewards, mask, eps=0.002):
        log_w = log_ratio(logp, old_logp, mask)
        log_sequence_ratio = masked_mean(log_w, mask, dim=-1)
        advantage = self.advantage(rewards)
        objective = clipped_objective(log_sequence_ratio, advantage, 1 - eps, 1 + eps)
        return -objective.mean()
~~~

#### CISPO

Once a positive-advantage token hits the PPO ceiling, more reuse of that rollout gives it no gradient. Clipped IS-weight Policy Optimization (CISPO) caps the importance weight and keeps the gradient through the sampled token's log-probability.

$$
\begin{aligned}
\bar w_{it}&=\operatorname{stopgrad}\!\left(\operatorname{clip}(w_{it},\ell,u)\right),\\
J_{\rm CISPO}&=\mathbb E_\mu\!\left[
\frac{\sum_{i,t}\bar w_{it} A_i\log\pi_\theta(y_{it}\mid s_{it})}{\sum_i T_i}\right].
\end{aligned}
$$

Its score coefficient is $$\bar w_{it}A_i$$. The original experiments cap the ratio above and allow it to approach zero from below.

class CISPO(GRPO):
    def loss(self, logp, old_logp, rewards, mask, lower=0.0, upper=2.0):
        log_w = log_ratio(logp, old_logp, mask).detach()
        weight = log_w.clamp_max(math.log(upper)).exp().clamp_min(lower)
        advantage = self.advantage(rewards).unsqueeze(-1)
        objective = weight * advantage * logp.masked_fill(~mask, 0)
        return -masked_mean(objective, mask, dim=(-2, -1)).mean()
~~~

</details>

#### SAPO

Soft Adaptive Policy Optimization (SAPO) makes the transition away from a full update gradual. It replaces the hard-clipped term with a sigmoid of the token ratio. Positive and negative advantages can use different temperatures.

$$
\begin{aligned}
v&=\sigma\!\big(\tau(w-1)\big),&
f_\tau(w)&=4v/\tau,&
f_\tau'(w)&=4v(1-v),\\
J_{\rm SAPO}&=\mathbb E_\mu\!\left[
   \frac1G\sum_i\frac1{T_i}\sum_t A_i f_{\tau_i}(w_{it})\right].
\end{aligned}
$$

The score coefficient is $$A_i w_{it} f'_{\tau_i}(w_{it})$$. At $$w=1$$ the gate has unit slope. Farther away, it smoothly shrinks the gradient relative to the raw ratio-weighted update.

class SAPO(GRPO):
    def loss(self, logp, old_logp, rewards, mask, tau_pos=1.0, tau_neg=1.05):
        advantage = self.advantage(rewards).unsqueeze(-1)
        tau = torch.where(advantage > 0, tau_pos, tau_neg)
        ratio = log_ratio(logp, old_logp, mask).clamp_max(30).exp()
        gate = 4 * torch.sigmoid(tau * (ratio - 1)) / tau
        return -masked_mean(gate * advantage, mask, dim=-1).mean()

#### DCPO

Doubling a token's probability from $$0.001$$ to $$0.002$$ is a much smaller probability move than doubling $$0.4$$ to $$0.8$$. Dynamic Clipping Policy Optimization (DCPO) uses the old probability $$q=\mu(a\mid s)$$ to set the clipping interval. With $$p=wq$$, its tolerance is on the probability-weighted ratio change $$\lvert w-1\rvert p$$.

$$
q|w^2-w|\le \epsilon,\qquad
\ell(q)=\frac{1+\sqrt{\max(1-4\epsilon_{\rm low}/q,0)}}2,\qquad
u(q)=\frac{1+\sqrt{1+4\epsilon_{\rm high}/q}}2 .
$$

The lower bound uses the branch adjacent to $$w=1$$ and floors at $$1/2$$. The upper bound grows as $$q$$ gets smaller. The paper caps the ratio used in the loss at $$10$$.

DCPO also computes $$a_{\rm now}$$ and $$a_{\rm all}$$ by standardizing the reward against the current group and all visits to the same prompt, respectively. On visit $$n$$, it takes whichever blend has the smaller absolute value as $$\tilde A_i$$.

$$
\begin{aligned}
h&=1/n, \qquad
\tilde A_i\in\big\{(1-h)a_{\rm now}+h a_{\rm all},\
                   h a_{\rm now}+(1-h)a_{\rm all}\big\},\\
J_{\rm DCPO}&=\mathbb E_\mu\!\left[
  \sum_i\frac1{T_i}\sum_t C_{\ell(q_{it}),\,u(q_{it})}
     \big(\min(w_{it},10),\tilde A_i\big)\right].
\end{aligned}
$$

An all-tie group on a later visit can contribute if its rewards differ from the historical mean. The code takes the cumulative statistics as inputs.

~~~python
class DCPO:
    def advantage(self, rewards, cumulative_mean, cumulative_std, visit):
        rewards = rewards.detach()
        current = rewards - rewards.mean(dim=-1, keepdim=True)
        current = current / rewards.std(dim=-1, keepdim=True, correction=0).clamp_min(1e-6)
        pooled = (rewards - cumulative_mean) / cumulative_std.clamp_min(1e-6)
        current_weight = 1 / visit
        smooth_current = (1 - current_weight) * current + current_weight * pooled
        smooth_pooled = current_weight * current + (1 - current_weight) * pooled
        return torch.where(smooth_current.abs() < smooth_pooled.abs(), smooth_current, smooth_pooled)

    def loss(self, logp, old_logp, advantage, mask, eps_low=0.16, eps_high=0.20, cap=10.0):
        q = old_logp.detach().masked_fill(~mask, 0).exp()
        q = q.clamp_min(torch.finfo(q.dtype).tiny)
        lower = 0.5 + 0.5 * (1 - 4 * eps_low / q).clamp_min(0).sqrt()
        upper = (0.5 + 0.5 * (1 + 4 * eps_high / q).sqrt()).clamp_max(cap)
        log_w = log_ratio(logp, old_logp, mask).clamp_max(math.log(cap))
        objective = clipped_objective(log_w, advantage.detach().unsqueeze(-1), lower, upper)
        return -masked_mean(objective, mask, dim=-1).sum(dim=-1).mean()
~~~

### When whole rollouts get stale

#### VESPO

With multiple updates per batch or an asynchronous sampler, many small token mismatches can multiply into one extreme response ratio. Variational Sequence-level Soft Policy Optimization (VESPO) uses the full ratio $$W_i$$ and replaces exact importance weighting with a bounded weight that fades in both tails.

$$
\begin{aligned}
W_i&=\frac{\pi_\theta(y_i\mid x)}{\mu(y_i\mid x)}=\prod_t w_{it},&
\phi(W)&=W^{c_1}\exp\!\big(c_2(1-W)\big),\quad c_1,c_2>0,\\
\nabla J_{\rm VESPO}&=\mathbb E_\mu\!\left[
\frac1G\sum_i \phi(W_i) A_i^0\,\nabla_\theta\log\pi_\theta(y_i\mid x)\right].
\end{aligned}
$$

Here $$\phi(1)=1$$, and $$d\log\phi/dW=c_1/W-c_2$$ puts its peak at $$c_1/c_2$$. The power damps small ratios and the exponential damps large ones. In code the weight is detached so the gradient matches the displayed update.

~~~python
class VESPO:
    def loss(self, logp, behavior_logp, rewards, mask):
        advantage = (rewards - rewards.mean(dim=-1, keepdim=True)).detach()
        c1 = torch.where(advantage > 0, 2.0, 3.0)
        c2 = torch.where(advantage > 0, 3.0, 2.0)
        log_w = log_ratio(logp, behavior_logp, mask).sum(dim=-1).detach()
        weight = (c1 * log_w + c2 * (1 - log_w.exp())).exp()
        sequence_logp = logp.masked_fill(~mask, 0).sum(dim=-1)
        return -(weight * advantage * sequence_logp).mean()
~~~

## Learning from fixed preferences

### DPO

A fixed preference dataset gives us a different starting point. Direct Preference Optimization (DPO) fits preferred and rejected responses without sampling fresh rollouts during training.

$$
\begin{aligned}
\pi^*(y\mid x)&=\frac{\pi_{\rm ref}(y\mid x)e^{R(x,y)/\beta}}{Z(x)},\\
\mathbb E_\pi[R]-\beta D_{\rm KL}(\pi\|\pi_{\rm ref})
 &=\beta\log Z(x)-\beta D_{\rm KL}(\pi\|\pi^*),\\
R(x,y)&=\beta\log\frac{\pi^*(y\mid x)}{\pi_{\rm ref}(y\mid x)}
       +\beta\log Z(x).
\end{aligned}
$$

Under the preference model $$P(y^+\succ y^-\mid x)=\sigma(R(x,y^+)-R(x,y^-))$$, the normalizer cancels for the pair. Substituting $$\pi_\theta$$ for $$\pi^*$$ gives a binary log loss.

$$
\ell_\theta(y)=\log\frac{\pi_\theta(y\mid x)}{\pi_{\rm ref}(y\mid x)},\qquad
L_{\rm DPO}=-\mathbb E\log\sigma\!\left(\beta[\ell_\theta(y^+)-\ell_\theta(y^-)]\right).
$$

class DPO:
    def loss(self, chosen_logp, rejected_logp, ref_chosen, ref_rejected, beta=0.1):
        difference = chosen_logp - rejected_logp
        ref_difference = (ref_chosen - ref_rejected).detach()
        return -F.logsigmoid(beta * (difference - ref_difference)).mean()
~~~

~~~python
import math
import random

import torch
from torch.nn import functional as F


def masked_mean(values, mask, dim=None):
    total = values.masked_fill(~mask, 0).sum(dim=dim)
    return total / mask.sum(dim=dim).clamp_min(1)


def log_ratio(logp, old_logp, mask):
    return (logp - old_logp.detach()).masked_fill(~mask, 0)


def clipped_objective(log_w, advantage, lower, upper):
    lo = torch.as_tensor(lower, dtype=log_w.dtype, device=log_w.device).log()
    hi = torch.as_tensor(upper, dtype=log_w.dtype, device=log_w.device).log()
    bounded = torch.where(advantage > 0, log_w.minimum(hi), log_w.maximum(lo))
    bounded = bounded.masked_fill(advantage == 0, 0)
    return bounded.exp() * advantage
~~~
